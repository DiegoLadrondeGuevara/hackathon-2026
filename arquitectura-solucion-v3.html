Qué aporta cada plataforma

Las tres primeras ejecutan partes funcionales. Cloudflare y Grafana cumplen papeles transversales.

Núcleo · AWS AcademyDetectar y gestionar

Reportes, telemetría, tablas DynamoDB, colas, correlación y verificación con Step Functions. Fuente de verdad.

Análisis · GCPAprender del historial

BigQuery almacena tendencias; Cloud Run consulta Gemini para sugerir hipótesis revisables con datos depurados.

Continuidad · AzureEstado público separado

Static Web Apps + Functions + Table Storage muestran la última actualización conocida, aun si el portal AWS no responde.

Borde · CloudflarePortal HTTPS

DNS y proxy opcional delante de Amplify. Requiere dominio y validación TLS; no cubre automáticamente API Gateway.

SaaS · Grafana CloudSalud transversal

Métricas sin PII y verificaciones HTTPS de las tres nubes. No es fuente de verdad ni reemplaza monitoreo nativo.

Las tres observaciones del equipo

Qué aceptamos y qué cambia exactamente.

01 · Válida

Anomalía sin salida operativa

En v2 llegaba al bus, pero no a un consumidor que iniciara verificación.

Nuevo: ColaAnomalias → CorrelacionadoraDeAnomalias → Incidents → VerificarIncidente.

02 · Válida

Relación poco explícita

Las tablas existían, pero no se veía la regla para compartir un mismo incidente.

Nuevo: zona, cobertura y tiempo compatibles; puntero activo y incident_id compartido. Casos ambiguos a operador.

03 · Parcialmente válida

Azure con poco valor visible

La copia de estado aportaba separación, pero faltaba una página usable durante una caída del portal principal.

Nuevo: sitio de estado público en Azure, con last_synced_at y aviso de dato atrasado.

Mismo incident_id si hay coincidencia
Regla común en ambos órdenes: misma zona, antena que cubre esa zona y episodio temporal compatible. Si hay un candidato único, el reporte o la anomalía se enlazan al mismo incident_id; si hay varios, decide operaciones. Sin anomalía: diez clientes distintos en menos de 24 horas siguen creando una sospecha y disparan VerificarIncidente (Step Functions Standard).

Límites que el dibujo no debe ocultar

Qué sí podemos demostrar

  • Anomalía técnica → sospecha → verificación, sin esperar usuarios.
  • Reporte → mismo incident_id cuando la relación es verificable.
  • Estado público en Azure con hora de última sincronización.
  • IA de GCP como sugerencia al operador, nunca como decisión automática.

Qué falta validar en cuentas reales

  • LabRole, DynamoDB Streams y Step Functions en AWS Academy.
  • Dominio y certificados para Cloudflare + Amplify.
  • Azure Static Web Apps Free en la suscripción del equipo.
  • Cuota Grafana Cloud, token OTLP y métricas sin PII.

Grafana no necesita leer CloudWatch mediante un rol nuevo: la propuesta envía métricas de aplicación por HTTPS. Cloudflare no convierte automáticamente la API en un endpoint protegido por su proxy.
